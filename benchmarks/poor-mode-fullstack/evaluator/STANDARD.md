# 测试与评分标准

## 1. 固定环境

- Python 3.11、Flask 3.1、pytest 9。
- Node 22 或更高、Vue 3.5、TypeScript 5.9、Vitest 3.2。
- 前端时区固定为 `Asia/Shanghai`，locale 为 `zh-CN`。
- 数据库每个用例独立创建；不得复用上一个测试的状态。
- 候选模型只看到生成后的 `workspace`。

环境版本发生实质变化时，应提升基准版本并单独建榜，不能与旧成绩直接比较。

## 2. 总分（100）

### 功能正确性：70

- 后端 35：认证/归属 6、分页 5、校验 5、幂等 7、并发 5、事务 5、UTC 2。
- 前端 30：页码/边界/时区 7.5、竞态和错误保留 8、乐观回滚和防重复 9、幂等 key 1.5、错误映射 4。
- 跨端静态契约 5：纯文本渲染 2、稳定 key 1、创建防重复 1、同任务更新防重复 1。

参数化测试只有全部行通过才获得该 case 的分数，防止只补一个示例。每个精确分值以 `rubric.json` 为准。

### 工程质量：10

- 隔离 TypeScript 类型检查通过：3。
- 人工窄审 7：直接且内聚的业务逻辑 2，有意义的新边界测试 3，未扩大范围 1，命名与错误路径清晰 1。

人工分必须由非候选模型或人工 Reviewer 给出并写明一句证据；未审核时记 0，成绩标记为 provisional。不要用“代码看起来不错”直接给满分。

### 效率：10

- 墙钟时间 4：20 分钟内满分，20..45 分钟线性下降，超过 45 分钟为 0。
- 工具动作 3：18 次内满分，18..55 次线性下降，超过 55 次为 0。
- Worker 调用与返工 3：一次调用且无返工满分；第二次调用或一轮返工最多 1.5；更多为 0。

任何缺失指标该子项记 0 并标记 `metrics_incomplete`。这样不会奖励未记录，也不会把未知误写为高效率。

### 完整性与证据：10

- 受保护的任务、契约、原始公开测试和依赖脚本未被修改：5。
- 无 `.skip/.only`、伪造测试结果、隐藏 evaluator 副本、静态 Mock 替代真实后端等规避物：2。
- 最终报告声称的三条命令与评测实际结果一致，并明确未验证项：3。

修改受保护文件会将总分封顶 59，并标记 `integrity_violation`。明确硬编码隐藏输入、篡改评分器或读取评测端的运行应判本次无效，不进入主榜。

## 3. 派生能力指标

- `reasoning_index = hard_case_rate * step_efficiency * 100`。`hard_case_rate` 是 rubric 中 `hard:true` 的得分率；`step_efficiency` 在 18 个工具动作内为 1，之后按目标衰减。缺少动作记录则为 null。
- `diligence_index` 由功能类别覆盖率 50%、真实验证证据 25%、完整性 15%、完成报告 10% 组成。
- `slacking_index = 100 - diligence_index`。

“智力”和“偷懒”是操作性指标，不是人格判断。榜单应同时展示原始正确性、步数和耗时，避免一个合成数掩盖原因。

## 4. 成绩等级

| 总分 | 等级 | 使用建议 |
|---:|:---:|---|
| 90..100 | S | 可承担此类有边界的全栈修复，仍需 Leader 验收 |
| 80..89.99 | A | 主体可靠，复杂事务或竞态需抽查 |
| 70..79.99 | B | 可做低风险实现，需要独立测试与审查 |
| 60..69.99 | C | 只适合更窄、更机械的任务 |
| 0..59.99 | D | 不建议用于该复杂度的实现任务 |

若正确性低于 42/70，总分等级最高为 C；若受保护文件被改动，总分封顶 59；若判定无效则不分级。

## 5. 重复运行与排行

- 同模型、同精确版本至少 3 次，显示总分中位数、最好/最差和完成率。
- 模型别名、供应商、价格说明、上下文大小、Leader 模型和是否发生 fallback 必须分列记录。
- 模型升级、供应商路由变化或基准大版本变化时新建一行，不覆盖历史。
- 主榜只纳入 `valid` 且完整过程指标的运行；其他运行保留在明细中。
