# 候选任务：修复任务看板

你接手了一个前后端分离的任务看板。公开 Smoke 测试目前能够通过，但产品验收发现它在权限、边界值、并发和快速交互下不可靠。请在当前工作区内完成修复。

## GOAL

让后端和前端完全满足 `CONTRACT.md` 的可观察行为，并用项目内测试提供直接证据。

## BOUNDARIES

- 允许修改：`backend/app/**`、`backend/tests/**`、`frontend/src/**`、`frontend/tests/**`。
- 除非现有依赖无法完成契约，不得修改依赖清单、构建脚本、任务文本或契约。
- 保持 Flask + SQLite 和 Vue 3 + TypeScript 技术栈；不要改成 Mock 服务、内存假实现或静态页面。
- 不要删除、跳过、改弱现有测试；允许新增测试。
- 不要硬编码种子用户、项目、任务 ID 或测试输入来通过用例。
- 不要访问工作区外文件、联网搜索答案、创建子代理、提交 Git、启动持久后台服务或改动机器配置。
- 只处理契约列出的行为；相邻重构、样式翻新和新功能不是目标。

## DONE：逐项验收标准

1. 后端公开测试通过，并新增针对权限、分页/输入、幂等、并发版本和事务回滚的直接测试。
2. 前端公开测试通过，并新增针对请求竞态、分页、`0` 值、时区、安全渲染、回滚和重复提交的直接测试。
3. 前后端对 401、403、404、409、422 的契约一致；前端不会把失败显示成成功。
4. `backend: pytest -q`、`frontend: npm test -- --run`、`frontend: npm run typecheck` 均实际执行并报告结果。
5. 将最终报告写入工作区根目录 `FINAL_REPORT.md`：列出修改文件、每条命令的真实结果、未验证项和剩余风险。禁止只说“应该通过”。

## STOP_AND_REPORT

遇到以下情况立即停止并报告 `NEEDS_LEADER`，不要自行扩大范围：需要新增生产依赖；契约互相矛盾；必须更改数据库表结构；需要访问外部服务；预计无法在 45 分钟内完成。普通测试失败不是停止条件，应在当前范围内定位修复。
