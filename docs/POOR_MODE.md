# 穷鬼模式：以完成成本为目标

当前源码版本以根目录 [VERSION](../VERSION) 为准。本模式让 Leader 负责意图、边界与验收，Worker 执行工作；优化的是得到可信结果的总成本，包括主模型上下文、子模型上下文、调用、重试、返工和验证。低价模型或更多并行本身不能证明省钱。

## 按问题选择调用链

| 已知情况 | 必要路线 | 停止条件 |
| --- | --- | --- |
| adaptive 且所有直做条件成立 | 声明 `DIRECT:` → 一次局部动作 | 一次窄验证后停止；范围增长立即移交 Writer |
| 改动位置明确、常规可逆 | Implementer + 最窄自验证 | DONE 有直接证据，无强制独立门 |
| 缺少决定修改位置的事实 | Analyzer 回答一个问题 → Implementer | 不让两者重复全库调查 |
| 同一行为涉及多个文件 | 一个有界 Implementer 包 | 文件数量不等于交付物数量 |
| 可独立验收且无写入冲突的交付物 | 分包，满足依赖后并行 | 不为填满并发额度制造工作 |
| 公共契约或高风险变化 | 实现 → 已命名的 Tester / Reviewer 门 | 不能以节约调用为由跳过必要验收 |

Leader 在首次调用前确定必要角色与命令；任务简报只携带精确入口、失败证据、已定选择、写入所有权和四项契约。后续包复用带来源及版本/差异信息的证据，不复制完整聊天或日志。证据过期或冲突才重读。上下文压缩不得删掉错误、边界与未通过项。

## 失败处理

| 事件 | 操作 |
| --- | --- |
| 模型/推理档位被明确拒绝 | 不重试同一配置；按平台终止或回退 |
| 瞬时调用失败，已确认旧调用终止 | 核对检查点后，同包、同模型最多重试一次 |
| 超时，无法确认旧 Worker 是否仍在运行 | 停止该包，不启动第二个写入者 |
| FAIL / BLOCKED / NEEDS_LEADER / 质量不足 | 按具体未满足的 DONE 裁决，不能冒充模型故障 |
| 确定性拒绝或瞬时重试耗尽 | VS Code 最多一次同职责主模型回退；Codex 仅在显式 `parent-worker` 时调用对应 fallback；ZCode 0.8.0 停止 |
| 一轮针对性返工和一次复核仍未满足 | 明确交付未完成项，不换包名重置额度 |

用户禁止回退或明确限制花费时，以用户约束为准。所有替代调用都必须先解决原调用是否终止的问题；非幂等命令不能因“没收到结果”而盲目重放。

## 模板配置与运行事实

| 平台 | 源码请求的 Worker 模型 | 推理配置 | 模型失败后的边界 |
| --- | --- | --- | --- |
| VS Code | GLM-5.3-Flash (CodingPlan) (gcmp.zhipu) | 本仓库不提供独立子调用档位字段 | 最多一次显式说明的主模型回退 |
| ZCode | glm-5.3-flash | 四角色 high | 停止并报告配置问题 |
| Codex | 基础角色为 gpt-5.6-luna | Analyzer / Tester medium；Implementer / Reviewer high | 默认停止；显式 `parent-worker` 时一次同职责继承回退 |

这是当前模板声明，不证明客户端实际加载、模型可用、模型继承或计费。保留现有平台差异，不用未验证的新模型替换当前选择。

## 防止再次出现版本混用

- 根目录 `VERSION` 是发布版本来源；两个 marketplace 和 ZCode manifest 必须一致，由 `scripts/validate.py` 检查。
- [共享执行契约](../src/protocols/poor-mode.md) 是跨平台直做门槛、成本、上下文、写入所有权与失败规则的唯一维护入口。运行 `python3 scripts/sync_poor_mode.py --write` 更新四份 Leader 策略：VS Code strict/adaptive、Codex、ZCode。
- `python3 scripts/sync_poor_mode.py` 默认只读检查，已接入 `scripts/validate.py`；修改任何嵌入块而未同步会失败。各平台模型、工具与权限仍由原生模板负责。
- 源码更新不等于已安装环境更新。按 [Codex](CODEX.md)、[ZCode](ZCODE.md) 或 README 的对应安装命令更新目标，开启新会话后做 Smoke。全栈基准的版本独立于插件发布版本，不能一起批量替换。

## 如何证明改进有效

用相同初始工作区、任务、模型配置和验收要求比较旧/新规则，至少重复三次。先比较正确性和越界情况，再比较总调用、重试、返工、主子模型输入输出、墙钟时间和实际费用。未知指标留空；使用主模型回退的运行单列。不能将静态校验通过写成节省了某个百分比。

[全栈基准](../benchmarks/poor-mode-fullstack/README.md) 的单 Worker 赛道继续按其原合同运行；多包编排比较应单列记录，不能混入原低价模型主榜。此次仅完成协议与同步校验，未产生新的模型成绩或成本测量。
